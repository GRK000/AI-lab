# Frontend Plan

The frontend should visualize how the repository works internally, class by class.

## Goal

Build an interactive teaching and portfolio interface where a reviewer can inspect:

- a perceptron update
- a neuron forward pass
- dense layer matrix multiplication
- activation functions
- backpropagation gradients
- optimizer state updates
- dropout masks
- training curves

## Suggested Shape

Use a small React/Vite app with a Python backend only when needed. The first version can
be static and load JSON traces generated by Python scripts.

Recommended structure:

```text
frontend/
  src/
    views/
      PerceptronView.tsx
      NeuronView.tsx
      DenseLayerView.tsx
      BackpropView.tsx
      OptimizerView.tsx
      TrainingRunView.tsx
  public/traces/
```

## Trace-First Design

Instead of running Python directly in the browser first, add trace exporters:

```text
artifacts/traces/
  perceptron_or.json
  neuron_forward.json
  dense_backward.json
  optimizer_adam.json
```

Each trace should contain inputs, intermediate tensors, outputs and parameter updates.
The frontend can animate those steps.

## Views

1. Perceptron view: points, decision boundary, misclassified sample, weight update.
2. Neuron view: weighted sum, activation curve, prediction threshold.
3. Dense layer view: matrix multiplication with highlighted rows/columns.
4. Backprop view: gradients flowing from loss to earlier layers.
5. Optimizer view: compare SGD, Momentum and Adam parameter updates.
6. Training run view: loss, metric, validation curves and final predictions.

## Implementation Phases

1. Add JSON trace exporters in Python.
2. Build static React views that read trace files.
3. Add controls for step, play/pause and selected layer.
4. Add live runs through a lightweight FastAPI backend.
5. Add side-by-side comparison with sklearn or PyTorch outputs.

This keeps the frontend honest: it visualizes the actual implementation instead of
recreating a separate toy model in JavaScript.
